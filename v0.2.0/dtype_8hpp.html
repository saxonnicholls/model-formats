Detailed Description

dtype, the element types every format shares, and conversion between them.

Overview

One enumeration for the element types of dense tensors: the IEEE floats (F64, F32, F16), bfloat16, the two OCP eight-bit floats (E4M3 "fn": no infinities, one NaN; E5M2: IEEE-like), the signed and unsigned integers of 8 to 64 bits, and bool (one byte, 0 or 1). safetensors names them F64 ... BOOL; NumPy, GGUF and PyTorch map onto it in their own headers. Block-quantised GGUF types are not dtypes: they are gguf::ggml_type.

convert_elements turns a run of elements of one dtype into another: any number to a float type (through double; the narrow floats round to nearest even with core's ml::minifloat), and integers to integers when every value fits. A float to an integer is refused: it is never what a checkpoint conversion means.

Relationships
See also
snicholls::ml::minifloat (core's ml/minifloat.hpp), formats::tensor_view.
Implementations and variants

constexpr tables over the enumeration; convert_elements is a loop per element.

Guarantees and contracts

Every function but convert_elements is constexpr and noexcept. convert_elements writes nothing on failure. Elements are little-endian, as every supported format stores them.

Errors

convert_elements: bad_shape when the spans do not hold the same count, unsupported for a float to an integer, out_of_bounds for an integer that does not fit the target (or a bool other than 0 or 1).

Examples
const std::array<std::uint16_t, 3> bf16{0x3f80, 0x4000, 0xbf00}; // 1, 2, -0.5 as bfloat16
std::array<float, 3> f32{};
const auto r = convert_elements(dtype::bf16, std::as_bytes(std::span(bf16)), dtype::f32, std::as_writable_bytes(std::span(f32)));
Performance

benchmarks/dtype_benchmark.cpp: convert_elements bf16 to f32 against the hand-written loop (BENCHMARKS.md). Copies, bf16 to and from f32 and the 8-bit floats to f32 take fast paths; the rest go through double.

Tests and demos

tests/dtype_test.cpp, demos/dtype_demo.cpp.

Dependencies

Core's ml/minifloat.hpp, endian.hpp.

Known issues and gotchas

A host must be little-endian (x86-64, ARM64): a static_assert says so.

Status

Experimental.
