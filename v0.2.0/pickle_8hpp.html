Detailed Description

A restricted unpickler: the opcodes and globals of a PyTorch state dict, and nothing else.

Overview

A pickle is a program for a stack machine, and a general unpickler runs it: GLOBAL os.system and REDUCE is arbitrary code. This one interprets only what torch.save(state_dict) emits and builds plain data from it, never calling anything:

  • Opcodes: PROTO, FRAME, STOP, MARK, the memo (PUT, BINPUT, LONG_BINPUT, GET, BINGET, LONG_BINGET, MEMOIZE), NONE, NEWTRUE, NEWFALSE, the integers (BININT, BININT1, BININT2, LONG1 up to 8 bytes), BINFLOAT, the strings (BINUNICODE, SHORT_BINUNICODE, BINUNICODE8), the bytes (BINBYTES, SHORT_BINBYTES), the containers (EMPTY_TUPLE, TUPLE, TUPLE1 to TUPLE3, EMPTY_LIST, APPEND, APPENDS, EMPTY_DICT, SETITEM, SETITEMS), GLOBAL, STACK_GLOBAL, REDUCE, BUILD, BINPERSID.
  • Globals: collections.OrderedDict, torch._utils._rebuild_tensor_v2, torch._utils._rebuild_parameter, and the storage types (torch.FloatStorage ... torch.BoolStorage, the bfloat16 and float8 ones).
  • REDUCE of those globals only: OrderedDict() is a dict; _rebuild_tensor_v2(storage, offset, size, stride, ...) is a tensor record; _rebuild_parameter(tensor, ...) is that tensor. BUILD is accepted on a dict or tensor and its state discarded (an OrderedDict's _metadata). BINPERSID takes PyTorch's ('storage', type, key, location, numel) and makes a storage record.

Every other opcode and every other global is unsafe_pickle, naming it. Limits keep a hostile pickle from exhausting memory: objects, memo entries and nesting are bounded, and every length is checked against the bytes.

formats::pytorch::parse (the zip container around it)
Implementations and variants

One pass over the opcodes into an arena of objects referenced by index (so the memo and in-place SETITEMS behave as Python's do).

Guarantees and contracts

Nothing in the pickle is executed. unpickle never reads outside its span.

Errors

unsafe_pickle (an opcode or global outside the set, a REDUCE of anything else), truncated, bad_header (a stack underflow, a bad memo index, a malformed persistent id), too_large (a limit).

Examples
// pickle.dumps({"lr": 3}, protocol=2), then the classic attack: os.system("echo pwned")
using namespace std::string_view_literals;
const auto safe = unpickle(bytes("\x80\x02}q\x00X\x02\x00\x00\x00lrq\x01K\x03s."sv));
const auto attack = unpickle(bytes("\x80\x02" "cos\nsystem\n" "X\x0a\x00\x00\x00" "echo pwned" "\x85R."));
Performance

Not benchmarked: linear in the pickle, which holds no tensor data.

Tests and demos

tests/pytorch/pickle_test.cpp (hand-assembled pickles, including os.system and builtins.eval attempts), demos/pytorch/pickle_demo.cpp.

Dependencies

The standard library and core.

Known issues and gotchas

Pickles of protocol 2 to 5 are read; protocol 0 and 1 text opcodes (INT, STRING, ...) are refused.

Status
