Detailed Description

vocabulary: a tokenizer's tokens, merges and special tokens, and the rank lookup core's BPE takes.

Overview

A tokenizer as files carry it: the tokens by id (as text: byte-level BPE writes each byte as one printable code point, so "Ġhello" is the bytes " hello"), the merges in rank order, each token's type, and the special tokens. hf::parse_tokenizer and gguf::read_vocabulary fill it; gguf::write_vocabulary writes it.

For byte-level BPE (GPT-2, Llama 3, Qwen, DeepSeek, OLMoE), token_bytes() gives each token's raw bytes, which is what core's ml::bpe_encode_piece and the ml library's GPT-2 tokenizer take; bpe_ranks is the rank(bytes) function core's BPE calls. Core's merge loop uses the token id as the merge rank (tiktoken's rule), which agrees with Hugging Face's merge order exactly when the ids of merged tokens increase with their merge's rank: bpe_ranks::ids_follow_merges() checks it (true for GPT-2).

SentencePiece (Llama 1 and 2, Mistral's first tokenizer), WordPiece and Unigram vocabularies are read as tokens with their kind, so they can be inspected and converted, but token_bytes and bpe_ranks refuse them: core's tokenizer track will add their encoders, and this is the seam they plug into.

Relationships
See also
snicholls::ml::bpe_encode_piece (core), formats::hf::parse_tokenizer, formats::gguf::read_vocabulary
Implementations and variants

vocabulary (data) and bpe_ranks (an index over it).

Guarantees and contracts

bpe_ranks copies what it needs; the vocabulary may go after it is built. Lookups are O(1) on average.

Errors

token_bytes and bpe_ranks::make: unsupported for a kind that is not byte-level BPE, bad_header for a token that is not in the byte-level alphabet or a merge that names no tokens.

Examples
const auto bytes = v.token_bytes(); // each token's raw bytes, by id
const auto ranks = bpe_ranks::make(v); // core's rank(bytes)
std::array<std::uint32_t, 16> ids{};
std::array<snicholls::ml::bpe_part, 16> scratch{};
const auto n = snicholls::ml::bpe_encode_piece(" world", *ranks, ids, scratch);
Performance

Not benchmarked: built once per tokenizer.

Tests and demos

tests/vocabulary_test.cpp (core's BPE over a vocabulary built here), demos/vocabulary_demo.cpp.

Dependencies

Core's ml/bpe.hpp.

Known issues and gotchas

Added and special tokens (<|endoftext|>) are written as plain UTF-8 in byte-level files, not in the alphabet: token_bytes takes such a token as its UTF-8 bytes when its type is control or user-defined.
