Detailed Description

Model files on disk: memory-mapped reading of any format, and writing that a crash cannot leave half done.

Overview

mapped_file::open maps a file with ts-moveables' mapped_region, so the readers' views are views of the page cache: opening a 15 GB checkpoint maps it and parses the header, and a tensor's pages are read when it is first touched. open_model maps a file and reads it with convert::read_any. write_file replaces a file atomically with ts-moveables' write_file_atomically (durable: synced before the rename); write_streamed does the same for output too large to build in memory, writing the pieces into a mapped temporary beside the target and renaming it over the target when complete. save_tensors writes tensors in the format the path's extension names.

Relationships
See also
snicholls::mapped_region, snicholls::write_file_atomically (ts-moveables), formats::convert::read_any
Implementations and variants

A mapping, or the whole file read into memory when the file cannot be mapped (an empty file, a pipe, a file opened read-only: ts-moveables' region maps for writing too).

Guarantees and contracts

A mapped_file owns its mapping; moving it keeps every view valid (the address does not change). Writing never leaves a partial file at the target path: the temporary is removed on failure.

Errors

Files with the path and the operating system's message; the format readers' and writers' errors.

Examples
const auto saved = io::save_tensors(path, tensors); // written beside, renamed over: never half a file
const auto model = io::open_model(path); // mapped: the tensors are views of the page cache
Performance

Not benchmarked: the cost is the operating system's.

Tests and demos

tests/io/files_test.cpp, demos/io/files_demo.cpp.

Dependencies

ts-moveables (mmap/mapped_region.hpp, fs/file.hpp); POSIX.

Known issues and gotchas

ts-moveables maps files read-write: a file the process may not write is read into memory instead (proposal: a read-only mapping in ts-moveables). write_streamed's temporary-and-rename belongs in ts-moveables as a streaming write_file_atomically; it moves there when that exists (proposal).

Status

Experimental.
