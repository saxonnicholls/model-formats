Detailed Description

The sharded-checkpoint index, model.safetensors.index.json: which shard holds which tensor.

Overview

A checkpoint too large for one file is split into shards (model-00001-of-00004.safetensors ...) and an index: {"metadata": {"total_size": N, ...}, "weight_map": {"<tensor>": "<shard file>"}}. parse_index reads it, refusing a shard name that could leave the directory (an absolute path, .., a separator other than / within the name); write_index writes it with sorted keys; shard_names makes the conventional names.

Relationships
See also
formats::safetensors::parse, formats::io::model_dir (opens every shard)
Implementations and variants

One struct, three functions.

Guarantees and contracts

weight_map is sorted by tensor name; files() lists each shard once, sorted.

Errors

bad_json, duplicate_name, bad_header (a wrong shape), bad_argument (an unsafe shard name).

Examples
const auto ix = st::parse_index(R"({"metadata":{"total_size":96},
"weight_map":{"lm_head.weight":"model-00002-of-00002.safetensors",
"model.embed_tokens.weight":"model-00001-of-00002.safetensors"}})");
for (const auto& f : ix->files())
std::printf("shard %s\n", f.c_str());
std::printf("lm_head.weight is in %s\n", ix->shard_of("lm_head.weight")->c_str());
Performance

Not benchmarked: read once per checkpoint.

Tests and demos

tests/safetensors/index_test.cpp, demos/safetensors/index_demo.cpp.

Dependencies

nlohmann/json through core-adapters.

Known issues and gotchas

Metadata values other than total_size are kept as JSON text.
