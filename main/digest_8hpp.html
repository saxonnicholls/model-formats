Detailed Description

SHA-256 and SHA-1, for verifying what the Hub sends: an LFS file's SHA-256, a small file's git blob SHA-1.

Overview

The Hub names every file by a digest: a large (LFS or Xet) file by the SHA-256 of its contents, a small one by its git blob id, SHA-1 of "blob <size>\0" and the contents. Both are checked before a download is moved into the cache. digest hashes incrementally; sha256_hex and git_blob_sha1_hex hash a buffer; file_digest_hex hashes a file through its mapping.

The family's SHA-2 belongs to core (its approved, not yet written, hash/sha256.hpp), and base-encode-decode has none, so until core's lands this uses OpenSSL's, which the Hub client links for TLS anyway: a vetted implementation, not a new one. The calls switch to core's when it exists (proposal in family/proposals/model-formats.md).
