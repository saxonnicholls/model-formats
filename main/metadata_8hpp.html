Detailed Description

GGUF metadata to a model_config and a vocabulary, and back, for the architectures core describes.

Overview

read_model_config maps llama.cpp's keys for gpt2, llama (Llama and Mistral), qwen2, qwen3, olmoe and deepseek2 (DeepSeek-V2 and V3) onto core's transformer_config; write_model_config writes the keys llama.cpp reads for the same architectures. The mapping:

GGUF core
embedding_length, feed_forward_length, block_count, context_length d_model, d_ff, layers, context
attention.head_count, head_count_kv, key_length n_heads, n_kv_heads, head_dim
attention.layer_norm_epsilon / layer_norm_rms_epsilon norm, norm_eps
rope.freq_base, rope.scaling.* rope_base, rope_scaling (linear, YaRN)
attention.sliding_window window
expert_count, expert_used_count, expert_shared_count, expert_feed_forward_length the MoE fields
expert_gating_func (1 softmax, 2 sigmoid), expert_weights_norm, expert_weights_scale scoring, route_scale
expert_group_count, expert_group_used_count, leading_dense_block_count groups, leading_dense_layers
attention.q_lora_rank, kv_lora_rank, key_length_mla, value_length_mla, rope.dimension_count MLA's ranks and widths
nextn_predict_layers mtp_depth (and block_count less it)

Floats are stored as f32 and read back as the shortest decimal that round-trips, so 1e-5 is 1e-5 again. What GGUF does not carry: biases (read from the tensors: blk.0.attn_q.bias present), the embedding tie (no output.weight), the training-only weights (balance and z losses, the bias update rate, MTP's lambda): left at 0 with a note. RoPE: llama and deepseek2 are adjacent-pair (interleaved, the Q/K weights permuted at conversion); qwen2, qwen3 and olmoe are half.

read_vocabulary and write_vocabulary do the same for tokenizer.ggml.*: the model (gpt2, llama, bert, t5), the tokens, their types and scores, the merges, the special ids, and the chat template.

Implementations and variants

Guarantees and contracts

A configuration returned satisfies ml::valid. read_model_config(parse(write(...))) gives back the mapped fields.

Errors

unsupported (another architecture), bad_header (a required key missing, or a configuration core rejects).

Examples
model_config c;
c.arch = architecture::gpt2;
c.block = snicholls::ml::gpt2_small;
c.layers = 12;
c.vocab = 50257;
c.context = 1024;
writer w;
const auto written = write_model_config(w, c, "gpt2-small"); // gpt2.embedding_length, gpt2.block_count, ...
vocabulary v;
v.tokens = {"a", "b", "ab"};
v.merges = {"a b"};
write_vocabulary(w, v);
const auto bytes = w.write();
const auto f = parse(*bytes);
const auto back = read_model_config(*f);
Performance

Not benchmarked: read once per model.

Tests and demos

tests/gguf/metadata_test.cpp, demos/gguf/metadata_demo.cpp.

Dependencies

Core's ml/transformer_config.hpp.

Known issues and gotchas

OLMoE's whole-projection Q/K norm is not core's per-head qk_norm: noted, left none.
