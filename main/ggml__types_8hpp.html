Detailed Description

Every ggml tensor type: its GGUF code, name, block size and bytes per block.

Overview

A GGUF tensor's type is a ggml_type: a dense element type (F32, F16, BF16, F64, the integers, F8_E4M3) or a block-quantised format, where block_size consecutive elements of a row are stored together in type_size bytes. traits gives both for every type GGUF defines; row_bytes and tensor_bytes compute the size of a row and a tensor, refusing a row that is not a whole number of blocks. to_dtype / from_dtype map the dense types onto formats::dtype.

Where core has a block's layout (ml/quantize.hpp: Q8_0, Q4_0, MXFP4) the size here is checked against core's struct by static_assert, and traits(t).in_core says so; core's quantize / dequantize then convert. The other sizes are taken from ggml-common.h (llama.cpp, MIT) and belong in core: they move there when core's quantisation track adds the formats, and this table then checks them against core as it does the first three.

Relationships
See also
formats::gguf::file, snicholls::ml::block_q8_0 (core)
Implementations and variants

One constexpr table.

Guarantees and contracts

Everything is constexpr and noexcept. Unknown codes give none.

Errors

None: unknown types and partial blocks are std::nullopt.

Examples
const auto q8 = traits(ggml_type::q8_0); // 32 elements in 34 bytes
const auto row = row_bytes(ggml_type::q4_k, 4096); // a 4096-wide Q4_K row: 16 blocks of 144 bytes
const auto partial = row_bytes(ggml_type::q8_0, 100); // not whole blocks: none
Performance

Not benchmarked: a table lookup.

Tests and demos

tests/gguf/ggml_types_test.cpp (every size against ggml-common.h's formulas, the core three against core), demos/gguf/ggml_types_demo.cpp.

Dependencies

Core's ml/quantize.hpp.

Known issues and gotchas

Codes 4, 5 (Q4_2, Q4_3), 31 to 33 and 36 to 38 were removed from ggml and are not types.

Status

Experimental. The non-core rows move to core when it gains the formats.
