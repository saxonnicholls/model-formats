Detailed Description

llm.c's files: the GPT-2 checkpoint (float or bfloat16) and the token shard, read and write.

Overview

The ml library trains in llm.c's formats so the two read each other's files.

  • A checkpoint is 256 int32s of header (magic 20240326; version 3 for float32 parameters, 5 for bfloat16; then max_seq_len, vocab_size, num_layers, num_heads, channels, padded_vocab_size), then every parameter in llm.c's order: wte [Vp, C], wpe [T, C], ln1w, ln1b [L, C], qkvw [L, 3C, C], qkvb [L, 3C], attprojw [L, C, C], attprojb, ln2w, ln2b [L, C], fcw [L, 4C, C], fcb [L, 4C], fcprojw [L, C, 4C], fcprojb [L, C], lnfw, lnfb [C]. Matrices are [out, in], as PyTorch's Linear.
  • A token shard is 256 int32s (magic 20240520, version 1, the token count), then the tokens as uint16.

parse_checkpoint checks the header and the size and returns the sixteen tensors as views; write_checkpoint writes one from a shape and the flat parameters. parse_tokens / write_tokens do the same for shards.

Relationships
See also
formats::convert::export_llmc_gpt2 (to safetensors and GGUF), the ml library's apps/llmc_files.hpp
Implementations and variants

Header structs and four functions.

Guarantees and contracts

Views borrow the bytes. The header's sizes are checked against each other and the file before any view is made.

Errors

truncated, bad_magic, unsupported_version, bad_header (non-positive sizes, heads not dividing channels, padded vocabulary below the vocabulary), bad_shape (the file's length is not what the header says).

Examples
const lc::gpt2_shape s{.max_seq = 16, .vocab = 50, .layers = 1, .heads = 2, .channels = 8, .padded_vocab = 64};
const std::vector<float> params(lc::parameter_count(s), 0.01f);
const auto file = lc::write_checkpoint(s, dtype::f32, std::as_bytes(std::span(params)));
const auto ckpt = lc::parse_checkpoint(*file); // sixteen views, llm.c's order
Performance

Not benchmarked: a header check.

Tests and demos

tests/llmc/llmc_test.cpp, demos/llmc/llmc_demo.cpp.

Dependencies

The standard library and core.

Known issues and gotchas

The rows of wte beyond vocab_size (up to padded_vocab_size) are padding, zero in llm.c's files.
