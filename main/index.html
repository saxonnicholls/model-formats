model-formats

Read and write the machine-learning model file formats, and download models from the Hugging Face Hub, for the snicholls libraries (the ML training library first). C++20, header-only, namespace snicholls::formats, include root <snicholls/formats/...>.

Documentation: https://saxonnicholls.github.io/model-formats/ (the API reference, built from the headers on every push to main and for each release tag).

Conversion: any of these to safetensors, GGUF, .npz or .npy tensor by tensor, with casts and dequantisation (Q8_0, Q4_0 and MXFP4 through core); model-level export of our llm.c checkpoints to Hugging Face safetensors and to llama.cpp GGUF, and Hugging Face checkpoints to GGUF and back.

Hub: resolve a repository and revision to its commit and files; download with resume, parallel files, SHA-256 / git blob verification, into a cache laid out as huggingface_hub's (blobs/, snapshots/<sha>/, refs/); HF_TOKEN, HF_HUB_OFFLINE, HF_ENDPOINT, HF_HOME / HF_HUB_CACHE.

Tools: mf-inspect <file|dir>, mf-convert <in> <out>, mf-download <repo>[@rev] [--include pattern].

Where it sits in the family

  • core is the standard library only, with no I/O and no codecs: it owns the vocabulary this library speaks (result, ml::transformer_config, ml::minifloat, the ggml blocks of ml/quantize.hpp, ml/bpe.hpp).
  • core-adapters joins core to one third-party library each: here, nlohmann/json (snicholls::core_json).
  • ts-moveables owns the operating system: memory-mapped files (mmap/), atomic writes (fs/), the event loop, and the HTTP/1.1 + HTTP/2 client with TLS (http/client.hpp, tls/openssl.hpp).

Reading and writing model files needs files, networking and JSON together, so it is a library of its own above all three, pinning core, ts-moveables and core-adapters. The Hugging Face download uses ts-moveables' http::client over TLS and its file and mmap modules for the cache, and no other HTTP library (decided 2026-11-19).
