Detailed Description

A Hugging Face model directory (or Hub snapshot): configuration, tokenizer, chat template and every weight shard, opened at once.

Overview

open_model_dir reads what a transformers checkpoint directory holds: config.json (to a model_config), generation_config.json, tokenizer.json with tokenizer_config.json (to a vocabulary and the chat templates; chat_template.jinja too, where newer repositories keep it), and the weights: model.safetensors, or model.safetensors.index.json and its shards, or (only when there is no safetensors) pytorch_model.bin and its index, read through the restricted unpickler. Every weight file is mapped; the tensors are views of the mappings.

A sharded checkpoint is checked against its index: every tensor the index names is in the shard it names, no tensor is in two shards, and the shard names are safe (relative, no ..).

Implementations and variants

One function into one struct.

Guarantees and contracts

The model_dir owns its mappings; its tensor views are valid while it lives, and moving it keeps them valid.

Errors

not_found (no config.json, no weights), Files, the parsers' errors, duplicate_name (a tensor in two shards), bad_header (a tensor missing from the shard its index names).

Examples
const auto m = io::open_model_dir(dir); // config.json, tokenizer.json, model.safetensors (or shards), mapped
Performance

Not benchmarked: dominated by mapping the files.

Tests and demos

tests/io/model_dir_test.cpp (a directory written by the test, sharded and not), demos/io/model_dir_demo.cpp.

Dependencies

ts-moveables, through io/files.hpp.

Known issues and gotchas

A configuration this library does not map (model_type "bert") still opens: config is then none and config_error says why.

Status

Experimental.
