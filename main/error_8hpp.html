Detailed Description

The library's one error type, formats::error, and formats::result<T>.

Overview

Every reader, writer and the Hub client report an expected failure as a value: a result<T>, which is core's snicholls::result<T, error>. An error is a code (errc, what kind of failure, for a program to branch on) and a message (where and why, for a person). Exceptions are not used for malformed input: a model file from the internet is untrusted, and a malformed one is an expected outcome.

Relationships
See also
snicholls::result (core's result.hpp)
Implementations and variants

One enumeration, one struct.

Guarantees and contracts

to_string is noexcept and never returns null. An error owns its message.

Errors

None of its own.

Examples
result<int> parse_rank(int r)
{
if (r < 0 || r > 8)
return fail(errc::bad_shape, "rank " + std::to_string(r) + " is not 0 to 8");
return snicholls::ok(r);
}
Performance

Not benchmarked: only on failure paths.

Tests and demos

tests/error_test.cpp, demos/error_demo.cpp.

Dependencies

Core's result.hpp; <string>.

Known issues and gotchas

A message may quote a name from the file (a tensor name, a key), cut to 64 characters; it never quotes a secret (the Hub token is never part of an error).

Status

Experimental.
