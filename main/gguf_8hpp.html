Detailed Description

GGUF (versions 2 and 3): read (validated, zero-copy) and write, every metadata type, arrays, tensors.

Overview

A GGUF file is a header (magic GGUF, version, tensor and metadata counts), the metadata (key, type, value), the tensor infos (name, dimensions innermost first, ggml type, offset), padding to the alignment (general.alignment, default 32), then the tensor data, each tensor at an aligned offset. llama.cpp's docs/gguf.md is the reference.

parse returns a file whose keys, strings and tensor data are views into the bytes given: nothing is copied, so opening a mapped model costs the metadata walk alone. A value is decoded on access; an array of strings is walked once by strings(). Validation: the magic and version; every length, count and offset checked against the bytes left before it is used (a 2^64 count is refused, not allocated); at most 4 dimensions; every row a whole number of blocks; every tensor aligned, inside the data, and not overlapping another; keys and tensor names unique; nested arrays at most 8 deep.

writer builds a file: set keeps insertion order (replacing a key in place), add_tensor takes the shape outermost first (as every other format here) and writes ggml's order, and the output is deterministic.

Relationships
See also
formats::gguf::ggml_type, formats::gguf::keys, formats::convert::model_config (GGUF metadata to core's transformer_config)
Implementations and variants

value (a view) for reading, metadata_value (owned) for writing; to_owned converts.

Guarantees and contracts

parse never reads outside its span and never throws on malformed input. Big-endian GGUF is refused.

Errors

truncated, bad_magic, unsupported_version, bad_header (an unknown value type, a bad alignment, too deep), too_large, bad_dtype (an unknown ggml type), bad_shape, misaligned, out_of_bounds, overlap, duplicate_name. Writing: duplicate_name, bad_shape, bad_argument.

Examples
const std::vector<float> norm(64, 1.0f);
std::vector<snicholls::ml::block_q8_0> q(2); // a 64-wide Q8_0 row, quantised by core
const std::vector<float> row(64, 0.5f);
snicholls::ml::quantize(row, std::span(q));
writer w;
w.set("general.architecture", value_string("llama"));
w.set("llama.block_count", value_u32(1));
const std::vector<std::string> tokens{"<s>", "a", "b"};
w.set("tokenizer.ggml.tokens", value_strings(tokens));
w.add_tensor("output_norm.weight", ggml_type::f32, {64}, std::as_bytes(std::span(norm)));
w.add_tensor("output.weight", ggml_type::q8_0, {1, 64}, std::as_bytes(std::span(q)));
const auto bytes = w.write();
const auto f = parse(*bytes); // views into `bytes`
for (const auto& t : f->tensors)
std::printf("%-20s %-5s %s, %zu bytes at %llu\n", std::string(t.name).c_str(), traits(t.type).name.data(), to_string(t.shape).c_str(),
t.data.size(), static_cast<unsigned long long>(t.offset));
Performance

Not benchmarked yet: the walk is linear in the metadata.

Tests and demos

tests/gguf/gguf_test.cpp (and the gguf-py cross-check, scripts/crosscheck.sh), demos/gguf/gguf_demo.cpp.

Dependencies

The standard library and core.

Known issues and gotchas

Keys and strings are bytes, not checked as UTF-8. Version 1 (32-bit counts) is not read.

Status

Experimental.
