Detailed Description

PyTorch's torch.save files (.bin, .pt, .pth), read safely: the zip, the restricted unpickler, the tensors as views.

Overview

Since PyTorch 1.6 torch.save writes a zip: <Archives>/data.pkl (the pickled object), <Archives>/data/<key> (one member per storage), <Archives>/byteorder, <Archives>/version. parse opens the zip, runs unpickle on data.pkl (never Python's unpickler: nothing in the file is executed), and turns every tensor of the state dict into a tensor_entry whose bytes are a view into its storage's member. Nested dicts ({"model": {...}}) are flattened with .; values that are not tensors (an epoch, a learning rate) are listed in skipped.

A tensor that is contiguous (row-major strides) has data, a view; one that is not (a transposed view saved as is) has contiguous == false, and materialize copies it into row-major order.

The legacy format (before 1.6: a pickle of pickles, with tensors after it) and anything not a zip are unsupported; use torch.save with its default zip format, or convert the checkpoint to safetensors.

Implementations and variants

One parse; one copy for non-contiguous tensors.

Guarantees and contracts

Read-only: nothing writes PyTorch files here (write safetensors). Every tensor's extent is checked against its storage, and every storage against its member, before a view is made.

Errors

The unpickler's (unsafe_pickle above all), zip's, and: bad_magic (not a zip), unsupported (the legacy format, big-endian, an unknown storage type), not_found (no data.pkl, or a storage member missing), out_of_bounds (a tensor outside its storage), bad_header (a state dict of the wrong shape).

Examples
const auto ckpt = pytorch::parse(*file); // the restricted unpickler: nothing in the file runs
for (const auto& t : ckpt->tensors)
std::printf("%s %s %s contiguous=%d\n", t.name.c_str(), safetensors_name(t.type).data(), to_string(t.shape).c_str(), t.contiguous);
Performance

Not benchmarked: the pickle holds no tensor data, so parsing is fast; views copy nothing.

Tests and demos

tests/pytorch/checkpoint_test.cpp (an archive assembled by hand as torch.save writes it), demos/pytorch/checkpoint_demo.cpp.

Dependencies

The standard library and core.

Known issues and gotchas

Two tensors may share one storage (tied weights): both are listed, viewing the same bytes.
