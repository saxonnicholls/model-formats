Detailed Description

Hugging Face's tokenizer.json and tokenizer_config.json to a vocabulary, and the chat template.

Overview

parse_tokenizer reads the tokenizers library's file: the model's type (BPE, WordPiece, Unigram), its vocabulary and merges (either form: "a b" strings or ["a", "b"] pairs), the added tokens (special ones become control tokens) and which alphabet BPE uses (a ByteLevel pre-tokenizer or decoder means byte-level; byte_fallback means SentencePiece). parse_tokenizer_config adds tokenizer_config.json: the special tokens by name, whether BOS and EOS are added, and the chat template, exposed as text (a Jinja template; nothing here renders it).

Relationships
See also
formats::vocabulary, formats::bpe_ranks, formats::gguf::write_vocabulary
Implementations and variants

Two parsers into one tokenizer struct.

Guarantees and contracts

The vocabulary's tokens cover every id from 0 to the largest; an id no token names is "[PAD<id>]", unused, as llama.cpp's converter writes it.

Errors

bad_json, bad_header (a wrong shape, a token id twice), unsupported (a model type not listed).

Examples
auto tok = hf::parse_tokenizer(R"({"added_tokens":[{"id":3,"content":"<|im_end|>","special":true}],
"pre_tokenizer":{"type":"ByteLevel"},"model":{"type":"BPE","vocab":{"h":0,"i":1,"hi":2},"merges":["h i"]}})");
const auto cfg = hf::parse_tokenizer_config(*tok, R"({"eos_token":"<|im_end|>",
"chat_template":"{% for m in messages %}<|im_start|>{{ m.role }}\n{{ m.content }}<|im_end|>\n{% endfor %}"})");
Performance

Not benchmarked: read once per model.

Tests and demos

tests/hf/tokenizer_test.cpp, demos/hf/tokenizer_demo.cpp.

Dependencies

nlohmann/json through core-adapters.

Known issues and gotchas

The pre-tokenizer's split pattern is not read: core's tokenizer owns the patterns it supports.

Status

Experimental.
