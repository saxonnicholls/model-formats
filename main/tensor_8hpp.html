Detailed Description

tensor_shape, tensor_view (a name, a dtype, a shape and bytes, borrowed) and tensor (owned).

Overview

The common currency of the readers and writers. A reader returns tensor_views whose data points into the bytes it was given (a mapped file, usually), so opening a 10 GB checkpoint copies nothing; a writer takes a span of tensor_views. tensor owns its name and bytes, for the results of a conversion.

Shapes are written outermost first (row-major, as safetensors, NumPy and PyTorch write them); GGUF's reversed order is converted at the GGUF boundary.

Relationships
See also
formats::dtype, formats::safetensors::file, formats::gguf::file
Implementations and variants

tensor_shape is a fixed array of max_rank extents and a rank: trivially copyable, no allocation.

Guarantees and contracts

A tensor_view borrows: the bytes behind name and data must outlive it. elements() and byte_size() return none on overflow rather than wrapping.

Errors

tensor_shape::push_back returns false past max_rank; checked_byte_size returns none on overflow.

Examples
const std::vector<float> weights(6, 0.5f);
const tensor_view v{"proj.weight", dtype::f32, {2, 3}, std::as_bytes(std::span(weights))}; // borrows `weights`
const tensor owned = tensor::from(v); // copies
Performance

Not benchmarked: plain data.

Tests and demos

Dependencies

Known issues and gotchas

A rank-0 tensor (a scalar) has one element.
