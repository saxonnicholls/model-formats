Detailed Description

Zip archives of stored (uncompressed) members, with ZIP64: the container of .npz and PyTorch's .pt.

Overview

NumPy's savez and PyTorch's torch.save both write zip archives whose members are stored, not compressed, and PyTorch aligns each member's data to 64 bytes so it can be mapped. parse reads the central directory (ZIP64 included, for archives and members over 4 GB) and returns each member's bytes as a view into the archive: nothing is copied or inflated. write writes such an archive, deterministically (fixed timestamps, the order given), with each member's data aligned (64 by default) by padding the local header's extra field, as PyTorch does.

Validation: the end-of-central-directory record is found within the last 64 KiB plus 22 bytes; every offset and size is checked against the archive before use; a member's local header must agree with the central directory's name length; data ranges may not overlap (the overlapping-member zip bomb); names are unique. A compressed member (deflate, savez_compressed) is unsupported, as are encryption and multi-disk archives. verify checks a member's CRC-32.

Relationships
See also
formats::numpy::parse_npz, formats::pytorch::parse
Implementations and variants

Read and write; a CRC-32 table (detail/crc32.hpp, to move to core's checksums).

Guarantees and contracts

parse never reads outside its span and never allocates in proportion to a size field it has not checked.

Errors

truncated, bad_magic (no end record), bad_header, out_of_bounds, overlap, duplicate_name, unsupported; verify: checksum_mismatch. Writing: duplicate_name, bad_argument (a name over 65535 bytes).

Examples
const std::string weights(256, 'w'), version = "3";
const std::vector<zip::member> members{{"archive/data/0", std::as_bytes(std::span(weights.data(), weights.size()))},
{"archive/version", std::as_bytes(std::span(version.data(), version.size()))}};
const auto bytes = zip::write(members); // stored, each member 64-byte aligned, as torch.save writes
const auto a = zip::parse(*bytes); // views into `bytes`
Performance

Not benchmarked: the directory walk is linear in the members; verify runs at CRC-32's byte-at-a-time speed.

Tests and demos

tests/archive/zip_test.cpp (and Python's zipfile in scripts/crosscheck.sh), demos/archive/zip_demo.cpp.

Dependencies

The standard library and core.

Known issues and gotchas

Data descriptors (flag bit 3) are accepted: the central directory's sizes are authoritative.
